What is a UUID?

A UUID (Universally Unique Identifier) is a 128-bit identifier usually written as 32 hexadecimal characters in five hyphen-separated groups, 8-4-4-4-12, such as 3f2504e0-4f89-41d3-9a0c-0305e82c3301. Microsoft calls the same structure a GUID (Globally Unique Identifier). The big advantage of UUIDs is that you can create them anywhere, on any number of machines at once, without asking a central counter or database, and still be practically certain they will never collide. That makes them popular in distributed systems, offline-first mobile apps, file names, request tracing and test data.

UUIDs are defined today by RFC 9562, which replaced RFC 4122 in 2024 and added versions 6, 7 and 8. The 13th character of a UUID shows its version and the 17th its variant. A third group starting with "4" means version 4, and a fourth group starting with 8, 9, a or b means the standard RFC variant.

Version 4 vs version 7

Version 4 is random: 122 of its 128 bits come from random numbers and the other 6 bits encode the version and variant. Nothing can be read from it and it is very hard to guess. The downside is that as a database primary key, new rows land in random places in the index, which slows down inserts on large tables.

Version 7 was designed to fix that. Its first 48 bits are a Unix timestamp in milliseconds and the rest is random, so newer UUIDs sort after older ones and are appended to indexes in order. The creation time can also be read back out, which the validator does for you. If you do not want the time to be visible, for example in public links, stick with version 4.

Can two UUIDs ever be the same?

In theory yes, in practice no. Version 4 has 2122, about 5.3 × 1036, possible values. By the birthday problem you would need to generate around 2.7 × 1018 UUIDs before the chance of a single duplicate reached 50%, which is a billion UUIDs every second for about 85 years. That guarantee depends on good randomness, so this tool uses the browser’s cryptographic crypto.getRandomValues and crypto.randomUUID functions, never predictable sources such as Math.random.

What the format options are for

  • Lowercase (default): The standard recommends lowercase output and most languages and databases produce it.
  • Uppercase: Some Windows tools, registry entries and older systems expect uppercase. The value is the same; only the spelling changes.
  • No hyphens: A continuous 32-character string, handy in file names, URLs or fields with a length limit.
  • Braces: The {3F2504E0-…} form is common in .NET, COM and the Windows registry.

Good practice

A UUID is an identifier, not a password or access key. Even though version 4 is hard to guess, use purpose-built, sufficiently long random tokens with expiry for security-sensitive things like password reset links or session keys. When storing UUIDs in a database, a native uuid type or 16-byte binary column saves space and is faster than text: uuid in PostgreSQL, BINARY(16) in MySQL and uniqueidentifier in SQL Server.

Frequently asked questions

Are UUID and GUID the same thing?

Yes, structurally they are identical. GUID is Microsoft’s name for the same 128-bit identifier. Spelling differences such as uppercase or braces do not change the value.

Which UUID version should I use?

Version 4 suits most purposes. If the IDs will be database primary keys and you want rows inserted in time order, version 7 performs better.

Are the generated UUIDs really unique?

The chance of a collision is negligible in practice. Version 4 has about 5.3 × 10³⁶ possible values and this tool uses a cryptographic random number generator.

Can I read a date from a version 7 UUID?

Yes. The first 48 bits are a Unix timestamp in milliseconds. Paste a version 7 UUID into the validator and it shows when it was created.

How many UUIDs can I generate at once?

Anything from 1 to 1000. Run it again if you need more; each run produces new random values.

Can I use a UUID as a password or security token?

It is not recommended. A UUID is an identifier; for security tokens use values designed for that purpose, with enough length and an expiry.

What is the nil UUID?

It is 00000000-0000-0000-0000-000000000000, with every bit zero, used to mean “no value”. The validator recognises it.

Are my UUIDs stored anywhere?

No. They are generated entirely in your browser and are never sent to a server or saved.
